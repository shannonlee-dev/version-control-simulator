# 버전 관리 모델 설계

## 커밋과 브랜치

커밋은 ID를 키로 하는 딕셔너리에 저장하고 브랜치는 이름에서 현재 커밋 ID로 연결합니다. ID는 세션 안에서 순서대로 생성됩니다. 부모 ID는 커밋에, 자식 연결은 별도 인덱스에 저장합니다. 새 커밋이 기존 부모만 참조하므로 커밋 그래프는 DAG입니다.

기본 로그는 생성 순서로 출력해 부모가 자식보다 먼저 나옵니다. 작성자·날짜 정렬을 명시한 로그는 선택한 정렬 기준을 따릅니다. `merge`는 두 부모를 갖는 커밋을 생성하며 실제 파일 병합이나 충돌 해결을 구현하지 않습니다.

## 탐색과 검색

`PATH`는 부모·자식 연결을 모두 사용해 커밋 간 경로를 너비 우선 탐색합니다. `ANCESTORS`는 부모 방향만 따라갑니다. 두 명령의 탐색 방향을 구분해야 합니다.

커밋을 추가할 때 정규화한 작성자와 메시지 키워드의 역색인을 갱신합니다. 검색은 역색인으로 후보를 얻은 뒤 생성 순서로 결과를 출력합니다. 결과 정렬을 위해 전체 생성 순서를 확인하므로 검색 전체가 항상 상수 시간인 것은 아닙니다.

## 정렬과 파일 비교

일반 정렬은 직접 구현한 안정 삽입 정렬을 사용합니다. 벤치마크는 안정 병합 정렬과 비교합니다. 평균·최악 시간복잡도는 각각 O(n²), O(n log n)입니다. 파일 diff는 줄 단위 LCS를 사용합니다.

## 검증과 경계

`make smoke`는 실제 REPL과 `examples/diff/`의 비교 파일을 사용합니다. 종료하면 저장소 상태는 사라집니다. 실제 Git의 작업 트리·스테이징·디스크 저장·원격 통신은 다루지 않습니다.
